# NIKKE Auto Assistant

<p align="center"><img src="docs/nikke-cover.jpg" width="180" alt="NIKKE Automation 專案封面與 App 圖示" /></p>

《勝利女神：妮姬》（GODDESS OF VICTORY: NIKKE）Android 畫面辨識與點擊輔助工具。

> **非官方、實驗性專案。** 本工具不隸屬於遊戲開發或發行公司。自動化操作可能受到遊戲服務條款限制，使用者須自行評估風險。目前辨識演算法仍可能漏判或誤點，請勿在無人監看時依賴本工具。

## Android 版本與介面

本專案提供兩個使用相同辨識與自動化核心的 APK：

| 版本 | 介面 | Application ID |
| --- | --- | --- |
| **Modern** | 深色科技風 **Android 原生 UI** | `com.example.nikkeauto.modern` |
| **Classic** | 原始簡易設定頁，適合測試與除錯 | `com.example.nikkeauto.classic` |

**Modern 目前不使用 HTML/WebView 介面。** Modern 的原生 UI 程式位於 `ModernUi.kt`。兩個版本可同時安裝，但請避免同時啟用兩份無障礙自動化服務，以免重複點擊。

## 功能

- **劇情／結算**：偵測 SKIP、結算繼續畫面與部分升級獎勵彈窗，嘗試自動點擊。
- **戰鬥準備**：優先點擊可用的橘色「快速戰鬥」；不可用／沒有時，嘗試點擊藍色「進入戰鬥」。
- **野外尋敵（實驗性）**：偵測怪物紅色光圈、藍色中心紅圈、導航驚嘆號與 Boss 標記。
- **巡弋（實驗性，預設關閉）**：無目標時嘗試縮放、滑動尋敵。
- **失敗處理**：偵測 `OPERATION FAILED`／逾時後嘗試「返回」，並停止地圖尋敵及巡弋。
- **暫停／繼續／停止**：保留螢幕擷取授權的暫停與繼續；完全停止後下次啟動需要重新授權。

以上為目前程式設計行為，不代表每個遊戲畫面都已通過實機測試。

## 安裝與使用

1. 從 GitHub **Actions** 選擇成功完成的 `Build Android APK (Modern + Classic)` 工作流程。
2. 在 **Artifacts** 下載 `NIKKE-Automation-Modern-APK` 或 `NIKKE-Automation-Classic-APK`。
3. 安裝 APK（Android 10 以上，主要針對 Android 14 測試）。
4. 在 App 中開啟無障礙設定，啟用對應版本的服務。僅在信任自行編譯的 APK 時，才允許 Android 的「受限制的設定」。
5. 點選螢幕擷取授權，**選擇整個螢幕**，然後切換到遊戲。
6. 依需要開啟各個功能模組；先關閉實驗性巡弋，確認辨識結果後再啟用。
7. 遇到異常可暫停，返回 App 查看。

無障礙權限可執行螢幕點擊，螢幕擷取權限可讀取螢幕內容；請審慎授權。

## GitHub Actions 編譯

使用 Java 17 / Android Gradle Plugin，工作流程定義於 `.github/workflows/build-apk.yml`。

```bash
gradle --no-daemon :app:assembleModernDebug :app:assembleClassicDebug
```

APK 輸出：

```text
app/build/outputs/apk/modern/debug/app-modern-debug.apk
app/build/outputs/apk/classic/debug/app-classic-debug.apk
```

Debug APK 僅供測試，正式散布應配置合適的簽章及版本管理。

## 技術架構

- **Kotlin / Android**
- **AccessibilityService**：透過 `dispatchGesture` 執行點擊及滑動。
- **MediaProjection / ImageReader**：取得螢幕畫面。
- **Google ML Kit 中文文字辨識**：辨識 SKIP、戰鬥和結算相關文字。
- **像素色彩與圖像特徵分析**：尋找快速戰鬥按鈕、怪物紅圈等。
- **EventLog**：App 私有空間的操作紀錄。

主要程式位於 `app/src/main/java/com/example/nikkeauto/`：

| 檔案 | 用途 |
| --- | --- |
| `MainActivity.kt` | 雙版本介面入口與權限流程 |
| `ModernUi.kt` | Modern 原生 UI |
| `CaptureService.kt` | 擷取畫面、辨識流程與狀態控制 |
| `TapService.kt` | 無障礙觸控手勢 |
| `BattleDetector.kt` | 戰鬥按鈕辨識 |
| `MapDetector.kt` | 野外敵人及導航辨識 |
| `SkipDetector.kt` | SKIP 圖像辨識 |
| `Settings.kt` | 功能開關與執行狀態 |

## 已知限制

- 螢幕比例、遊戲更新、文字語系、特效與縮放可能造成辨識失準。
- 大地圖怪物、Boss、導航和巡弋邏輯仍屬實驗性。
- SKIP 和「返回」操作依賴當前畫面判斷，可能因 OCR 或畫面配置不同而無法觸發。
- 點擊派送成功不等於遊戲已接受操作；請以遊戲畫面變化確認。
- 本專案目前沒有宣稱支援完全無人值守的自動通關。

3. **每日派遣**：前哨基地、派遣公告欄、全部領取及全部派遣。
4. **普通商店免費商品**：信用點商品；僅在確認消耗鑽石為 0 時嘗試購買。
5. **每日免費禮包**：付費商店、普通禮包、每日、免費。
6. **好友點數**：好友清單、贈送及確認。
7. **每日升級**：依教學挑選低等級角色、升級一次（**預設關閉，會消耗遊戲資源**）。
8. **新人競技場**：方舟、競技場、ROOKIE、快速戰鬥與結果（**預設關閉，可能消耗挑戰次數**）。

這套流程使用 ML Kit OCR 及畫面相關文字約束進行保守點擊。圖片 PDF 為特定遊戲 UI、版本與語系示範；當 OCR 辨識不到或畫面不符合預期時會停止該動作，部分步驟需人工確認、返回首頁或按「略過至下一項」。**尚非完整、已實機驗證的一鍵全自動流程；不要在無人監看情況下運行。**

目前不包含自動刪除郵件、付費商品購買、儲值及其他非 0 鑽石商品購買。完整測試應先逐一開啟模組並驗證觸控座標。


## Material Design 3 與 OpenCV 視覺辨識

Modern 控制台與日常頁面採用 Google Material Components for Android（Material 3 主題、MaterialButton、MaterialSwitch），Classic 操作介面維持備用版本。

新的 `OpenCvVision.kt` 使用官方 Android OpenCV AAR（4.10.0）：HSV 青色外框篩選、形狀輪廓、亮色內部與深色驚嘆號驗證、候選中心定位。藍色導航辨識先嘗試 OpenCV，不適用或初始化失敗則回退原本的 `MapDetector.kt`，現有 `MapNavigationState.kt` 防重複導航機制保留。

設計參考來源（**未直接複製第三方程式碼**）：
- [Nain57/Smart-AutoClicker](https://github.com/Nain57/Smart-AutoClicker)：畫面辨識條件驅動點擊的架構概念
- [jinpf/AutomatorX](https://github.com/jinpf/AutomatorX)：跨解析度圖形定位、確認才動作
- [onlyfish79/recordAutoTestScript](https://github.com/onlyfish79/recordAutoTestScript)：影像匹配與觸控座標驗證思路

OpenCV 自身為 Apache-2.0 授權。此處採用獨立撰寫的 Kotlin 視覺實作，並未整合 Smart-AutoClicker（GPL-3.0）或第三方專案中授權不明的來源程式。

注意：目前新版使用的是 OpenCV 輪廓偵測，尚未收集足夠真實樣本建立多尺度原圖模板庫；偵測的準確率及跨設備位置映射需要 Redmi 和其他 Android 設備實機驗證。

依照使用者提供的三頁介面設計參考，Modern 改成**底部導覽列三分頁**，不用在首頁向下捲動尋找全部功能：

這些分頁共用同一個 Android Activity 的原生 Material 3 元件與自動化狀態，不會因切換分頁重新啟動擷取服務。Classic 繼續維持簡易介面。原本的 `DailyRoutineActivity` 保留兼容，但 Modern 日常模組直接整合在第三個分頁。


## 圖片比對備援與效能修正

- **實際圖片模板**：`app/src/main/assets/templates/blue_diamond_core.png` 為使用者提供的「!」導航菱形裁切縮小版本，用於 OpenCV Canny 邊緣特徵的多尺度 `matchTemplate`。
- **保留先前辨識器**：原有 OpenCV 青色輪廓及 `MapDetector.navigationDiamond` 先執行，兩者都未找到時才調用 `DiamondTemplateMatcher.find`；模板結果額外驗證青藍外框，降低地形誤判。
- **不卡主執行緒**：ML Kit OCR 結果與尋怪分析移到單一背景執行緒，`busy` 跨執行緒同步；若辨識 20 秒未完成，會暫停並提示重啟擷取。
- **測試限制**：已使用雪地截圖離線比對外框位置，但 APK 的實際效能、不同手機畫面比例及縮放情形仍需實機驗證。模板並非機器學習模型。


## 每日圖片元件與共用流程（信箱／競技場／掛機）

新增 `DailyScreenParts.kt`，根據使用者上傳的三份教學 PDF 及 `妮姬自動化.zip` 中的按鈕裁圖，抽象成共用畫面元件：

- **REWARD 結算**：遊戲中多個日常活動共用「點擊領取獎勵」；辨識畫面文字、確認位置並點擊
- **返回與關閉**：右上角 X、底部首頁；不能不確認頁面就按固定位置
- **入口與確認**：首頁郵箱／方舟／前哨防禦；每一步確認當前頁面才進下一步
- **限制消費**：「一舉殲滅」第一次免費可以嘗試；出現鑽石 50 等付費價格時只允許取消，不自動花鑽石
- **競技場**：方舟 → 競技場 → ROOKIE → 第三位對手 → 確認快速戰鬥 ON → 進入戰鬥 → 結算；至多三場，最後返回首頁

`DailyRoutine.kt` 已加入獨立「掛機獎勵」模組及開關，與「信箱領信」「新人競技場」共用新畫面判斷器。每日升級／競技場仍預設關閉，後者須手動啟用。進度顯示隨 `DailyRoutine.steps` 動態更新。

**實作範圍**：此階段將圖片教學中的入口、操作順序及相對位置轉成具 OCR 畫面守衛的 Kotlin 流程；**ZIP 圖片尚未逐張轉成 APK 內 OpenCV 模板**。畫面 OCR 不一致或按鈕模糊時可能停止，需要人工協助。完整自動化仍需在手機上驗證，以免誤觸、重複領取或錯誤消耗挑戰次數。


## 九模組每日流程共用規格（2026-11-02）

日常模組共用 `DailyCommon.kt`：以 ML Kit OCR 的文字邊界中心定位登入 `TOUCH TO CONTINUE`、活動及回歸公告的 X、伏特每日探索領獎，以及辨識 REWARD 提示；沒有辨識到 X 位置時不盲點固定座標。每次日常點擊後等待至少 3 秒，重新截圖辨識。

九項模組依序為：登入與彈窗、信箱、掛機獎勵、派遣、免費商店商品、每日免費禮包、好友點數、每日升級及重置、新人競技場。新規範要求競技場**每日兩次免費對戰**，第 2 次對戰前先更新目錄；新版已改為最多兩場，OCR 看到「更新目錄」才點擊。首次免費一舉殲滅必須辨識到明確「每日首次免費」，若出現 50 珠寶則嘗試取消，無法確認時不點擊購買。

目前已上線共用登入及活動彈窗判斷，並收緊競技場和掛機獎勵安全條件。其餘模組的完整成功驗證、返回大廳，以及純圖示 X／信箱／首頁的真正圖像匹配仍需完善；不能視為九項流程都通過實機測試。尤其升級後的等級重置**尚未完整實作**，預設保持關閉。


## 預設登入功能與日常調試設定（2026-11-02）

- **進入遊戲／活動彈窗關閉**已從日常任務清單移出，作為自動化執行期間的預設共用功能。當 OCR 找到 `TOUCH TO CONTINUE`、活動／回歸公告右上角 X、伏特每日探索領獎等已知目標時，優先處理，再繼續推圖或日常。
- 日常分頁目前顯示 **8 個可開關的任務**（信箱、掛機、派遣、普通商店免費物品、免費禮包、好友、升級、競技場）；登入不再重複計入。
- 每一項日常任務現在有「**調試設定**」按鈕：可設定成功點擊後的等待時間、辨識失敗的重試間隔、重試次數及超限後暫停／略過。設定儲存在 Android SharedPreferences。
- 日常文字按鈕仍優先使用 ML Kit OCR 元件中心座標。辨識失敗**不盲點**。當重試超限，執行該項的安全失敗策略。
- 此版本是**模組層級調試**，不是逐個圖片元件的完整規則編輯器；純圖示仍有部分尚未建立模板。實機需逐個驗證。


## 遊戲內浮窗＋完整步驟規則編輯器（實驗版）

Modern 版「總控台」新增浮窗開關與規則編輯器；首次開啟浮窗會引導使用者授予 Android「顯示在其他應用程式上層」權限。迷你浮窗可拖曳、點擊展開，展開後可暫停／繼續、停止、略過目前日常步驟，並開啟浮動式 Material 3 規則編輯器。浮窗僅攔截自身位置的觸控，不覆蓋整個螢幕。

日常八項任務各自可編輯步驟：新增、修改、上下排序、刪除；辨識方式 `OCR`／`IMAGE`／`BOTH`、OCR 文字、圖片模板名稱、區域（全畫面／上下左右／中央）、成功動作（點擊／進下一步／等待／暫停）、失敗動作（重試／略過／回上一步／暫停）、每步等待與重試次數。規則以 JSON 儲存在 App 私有資料，可複製匯出或貼上匯入。

**圖片模板**：從浮動規則編輯器選取事先裁切好的 PNG/JPG，匯入後產生 `template_...` 名稱，並填入該步驟的圖片模板欄位。OpenCV 多尺度模板匹配提供位置；預設相似度門檻為 0.84。OCR 與圖片條件可共同使用。

**執行規則**：只有日常模組已存有啟用規則時，該模組才使用自訂規則執行器；沒有自訂規則的模組繼續使用原本流程。推圖尋怪核心不受規則編輯器控制。點擊後仍有等待與有限重試，找不到辨識目標時不任意點擊。

**目前限制與風險**：這是首次加入的實驗性規則編輯器，尚未完成手機實測。辨識區域只能選擇預設方位，尚無手指直接框選圖像的編輯器；自訂規則尚未加入拖曳滑動及多分支流程圖。Android 浮窗可能出現在 MediaProjection 擷取影像內，若遮住遊戲按鈕，需要縮小或移開。浮動編輯窗仍是 Activity Dialog，不是在浮窗內完全嵌入的拖曳面板。自訂 IMAGE/BOTH 模板應先測試辨識是否準確，尤其涉及商店與消費資源的規則需人工確認。


## 2026-11-02 日常原生步驟可編輯與浮窗啟動修復
